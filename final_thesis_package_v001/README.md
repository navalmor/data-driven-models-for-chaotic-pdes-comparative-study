# Final results package — data-driven models of the Kuramoto-Sivashinsky equation

This is the curated results package for the thesis: the KS dataset, the AE-SINDy reduced-order
models, the eight forecasting models, and every figure and table used in the write-up, together
with the exact configurations that produce them.

The package is built by running the pipeline, not by copying old outputs. Each configuration in
`configs/` is executed and its results land in `results/`. Building the package is itself the
reproducibility check. For the repository-level workflow and installation, see the root
[README](../README.md); for what the default reproduction checks, see
[../docs/validation.md](../docs/validation.md).

## The scientific chain

```
KS simulation (u_series.npy)
├── AE-SINDy latent-8 representation ──┬── latent-8 forecasting: NGRC · RC · PERC · PINN
│                                      └── post-hoc SINDy refit (threshold 0.025)
├── AE-SINDy latent-6 dynamics baseline
└── full-64 forecasting: NGRC · RC · PERC · PINN
```

The latent-8 dependency is the one to understand: four of the eight forecasting models do not
consume the physical field at all — they consume the autoencoder's latent trajectory, so their
quality is bounded by the representation as well as by the forecaster.

## How to reproduce

The supported path is the reproduction wrapper, run from the repository root:
[`../scripts/reproduce_final_thesis.py`](../scripts/reproduce_final_thesis.py). It reads the
validation contract in `repro_validation/`, validates the frozen artifacts by checksum, reruns
the reproducible results, and by default uses no GPU and does not re-run the solver.

```bash
source scripts/repro_env.sh                                         # thread pinning; source before Python starts
python scripts/reproduce_final_thesis.py --validate-existing --yes  # checks the package; runs no models
```

Configurations are ordered by dependency: the latent-8 forecasting configs read the AE-SINDy
export, so the frozen representation is validated first. See
[../docs/validation.md](../docs/validation.md) for the expected counts.

## Frozen results register

Most of this package is produced by rerunning the pipeline. A few results are frozen — copied
from a verified source rather than regenerated — where regeneration is not possible or not
meaningful. Each is recorded here honestly.

| result | status | why frozen | integrity |
|---|---|---|---|
| **KS simulation** (`results/00_simulation/`) | frozen dataset | Byte-identical regeneration is impossible for a chaotic trajectory spanning about 130 Lyapunov times: a rounding-level difference between environments is amplified to attractor scale. The solver is not re-run. | `u_series.npy` SHA-256 `85bb1902…`; validated by checksum |
| **AE-SINDy `latent6_trial002`** | frozen checkpoint + package-local reanalysis | The outcome is the frozen selected checkpoint. A full retrain was attempted and rejected (cross-environment GPU nondeterminism). The frozen model is reanalysed and visualised on the package simulation; it is not a from-scratch retrain. | reanalysis reproduces the canonical numbers exactly: horizon 8.8, decoder error 0.022894755, 17 active terms |
| **AE-SINDy `latent8_trial014_representation`** | frozen learned representation, checksum/shape validated | A GPU-trained representation, frozen and checksum-verified by default rather than retrained. Exact cross-hardware retraining is not claimed. All latent-8 downstream results reproduce from these exact bytes on CPU. | `model.pt` SHA-256 `6e6c38b5…`; validated by targets AE8-001…AE8-006 (checkpoint and metadata checksums, latent shapes, reconstruction MSE 0.006592637859284878, MAE 0.062012095004320145) |

The simulation freeze is the reproducibility boundary of the whole package: everything downstream
is defined against `results/00_simulation/u_series.npy`. Re-running the solver reproduces the
physics and statistics of the system, not the exact values. An optional same-stack GPU retraining
of the latent-8 representation is documented in
[../docs/advanced_latent8_gpu_retrain.md](../docs/advanced_latent8_gpu_retrain.md); it corroborates
the frozen artifact and is not the default path or a cross-hardware guarantee.

## What this package does not contain, and why

1. **The KS trajectory is a locked, checksummed dataset, not regenerated.** The system is chaotic
   and the dataset spans about 130 Lyapunov times, so a rounding-level difference between
   environments is amplified to the scale of the attractor. All results are defined against the
   checksum-verified dataset. This is a property of chaos, not a defect of the code.
2. **The raw optimiser-search output is not published, but the plot-relevant subset is.** The
   historical ~34 GB search trees are large and are not shipped. A compact, sanitised dataset of
   the 32 authoritative trial histories (3,040 successful trials) is shipped under
   `forecasting/data/optimizer_search/`, and all 24 optimiser diagnostic figures regenerate from
   it with the public plot configs. Scientific and visual reproduction is supported; identical
   cross-machine PNG checksums are not guaranteed.
3. **Reproducing the latent-8 forecasting models does not require a GPU.** The autoencoder does,
   so the package ships the latent arrays and the decoder, and the latent-8 forecasting results
   reproduce on CPU without retraining the autoencoder.

## Reading the figures: units

Three time conventions coexist on purpose, and mixing them up produces a wrong sentence.

| figures | convention |
|---|---|
| simulation, AE-SINDy time axes, forecasting per-model | Lyapunov time, `t·λ_max`, λ_max = 0.043 |
| all `tables/` numbers, seed-robustness boxplots, optimiser horizon axes | physical simulation time |
| optimiser x-axes, `xi_heatmap`, `training_history` | no time axis (trial / parameter / checkpoint) |

A horizon marker on a per-model forecasting figure equals `physical time × 0.043` and will not
match the horizon in `tables/`. That is intended behaviour. Quote numbers from `tables/`; never
measure them off an axis.

## Reading the optimiser-search figures correctly

They are appendix diagnostics, not performance evidence, and the distinction is not cosmetic.

- **NGRC** is deterministic. Its search is its selection procedure, so its search plots are direct
  selection evidence.
- **RC, PERC, PINN** are stochastic. Their finals were not taken at the optimiser's argmax. They
  were chosen by a validation-only 15-seed rerank of the top-10 candidates, taking the highest
  median horizon and its representative seed. Their search plots show candidate-pool exploration,
  and the heights are single-seed, search-time scores.

Search-time score is not the final metric, and the gap is the point: one PINN latent-8
configuration scored 28.8 in its search, and its final value is validation 10.4 / test 8.4. The
seed-robustness figures, not the optimiser plots, are the evidence for model quality.

## Seed-robustness figures

Five figures ship, one per seed-reranked stochastic model (`rc_full64`, `rc_latent8`,
`perc_full64`, `perc_latent8`, `pinn_latent8`). Each shows that model's 15-seed validation-horizon
distribution for each of its 10 re-ranked candidates. Selection used the median validation horizon
across the seeds, never the best seed; in every case the originally published value sits at or
above the top of its own candidate's box, so the earlier, higher numbers were a lucky draw rather
than a typical one. These are appendix diagnostics about the selection process, not final
performance.

`pinn_full64` was also seed-reranked, over 15 seeds under the same median-based rule, but through a
staged design of a different shape, so no matching boxplot ships. The deterministic NGRC models
have no seed distribution at all, so a seed test is undefined for them.

Final numbers live in `tables/`. Nothing else in this package should be quoted as a result.
